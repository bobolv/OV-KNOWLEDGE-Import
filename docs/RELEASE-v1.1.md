# v1.1 · Codex采集与人工审核

日期：2026-09-25。v1.0手动导入版的发布、标签和镜像保持不变。

## 已实现

- 独立采集凭据，单批至多6条；三个指定主题，摘要及内容必填。
- 规范化来源网址与来源版本去重，逐项成功或失败回执、最近30次采集记录。
- 自动保存Markdown知识笔记及摘要、标签、来源机构、日期、适用范围和注意事项。
- 初始状态“待导入 · 待审核”；人工明确确认后审核通过，再由人导入。未审核资料在服务端被阻止，批量操作亦跳过。
- 修改属性撤销当前审核。审核历史保留时间、填写的审核人、意见及内容指纹。
- 源笔记保留采集时原貌，人工修订后的当前摘要和审核说明写入OV的context.md，与source关联。

## 本机部署

源码位于`E:\work\docker-base\ov-records-portal`。运行Node 24的`scripts/setup-collector.mjs`创建独立凭据，再`docker compose up -d --build`。第一次部署到新机器时须创建或恢复外部卷`ov-records-portal_portal_data`；Compose内Tailscale绑定地址应修改为目标主机实际地址。用start.ps1设置管理员密码。凭据和数据不在源码包中。

当前镜像`ov-records-portal:1.1.0`；沿用已有外部数据卷与两个8787访问地址。升级前已停止门户取得完整卷快照：`backups/before-v1.1-20260925.tar.gz`。备份含业务资料和解密密钥，仅本机保管。

当前Codex本地定时任务“知识采集与待审入库”，每天北京时间09:00运行，每次最多6条。主机、Codex和Docker须可用。该任务在Codex中单独管理，不包含在Docker镜像内；迁移源码不会自动迁移定时任务。无新增保持安静，新增待审或失败时通知。

## 回退

先在Codex暂停采集定时任务，停止门户。将Compose镜像改为`ov-records-portal:v1.0-manual`，使用`docker compose up -d --no-build`运行本机保留的封版镜像。不要构建新代码覆盖该镜像。

为了避免v1.0不认识审核字段造成未审知识被当作普通资料导入，回退前必须恢复升级前的完整卷快照。先另备份当前卷，并保留升级后资料，避免丢失新记录；在确认恢复目标后再执行恢复。不要直接用v1.0读取当前v1.1业务卷进行批量导入。原始封版源码也可从v1.0-manual标签获取。
